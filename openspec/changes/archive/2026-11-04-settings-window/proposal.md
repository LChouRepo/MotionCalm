# Proposal

## Why

变更 1–3 之后，所有参数都能调，但只能通过托盘的少数几项、全局热键或手改 `MotionCalm.ini`。目标用户是不熟悉 INI 语法的朋友：调遮罩外观时看不到效果，改快捷键时不知道是否与其他程序冲突，校准记录也无处查看。变更 4 提供一个完整的中文设置窗口（DESIGN §12）：6 个分页覆盖 §8 的全部配置键；改动即时生效并自动保存；"预览强度"滑块让用户不动鼠标也能看到遮罩效果；快捷键页通过按键捕获来设置组合键，并当场提示冲突。

## What Changes

- 新增非模态、单实例的设置窗口"MotionCalm 设置"（资源脚本定义的对话框 + Tab 控件 + 6 个子对话框页：遮罩 / 参照物 / 触发 / 校准 / 快捷键 / 通用），只用 comctl32 v6 系统控件，Per-Monitor V2 DPI 感知，界面全部中文。
- 每个控件都绑定一个 INI 键，并有固定的范围与步长。改动立即写入 `Config`，发出 `ConfigChanged`，由 app 重新配置强度模型、渲染样式、热键、截屏与游戏判定；最后一次改动 300 ms 后保存 INI。
- 遮罩页"预览强度"滑块：窗口打开期间把它作为强度下限，并让 overlay 在游戏或设置窗口所在显示器上显示遮罩；关闭窗口即失效，不写入 INI。
- 快捷键页：每个热键动作一行，用自定义的按键捕获框设置（捕获修饰键 + 虚拟键；Backspace / Delete 清除为 None）。内部重复或被其他程序占用时标红，没有修饰键时给黄色警告。编辑期间暂停全局热键，改动后立即重新注册。
- 校准页：校准记录列表（exe、每度计数、日期），可删除、可发起重测；可修改"未校准时的每度计数"。
- 通用页：开机自启（与 `HKCU\...\Run\MotionCalm` 同步）、录屏可见性、日志级别、排除名单与"视为游戏"名单的增删、"清空已知游戏列表"、"打开配置文件"、"恢复默认设置"。
- 托盘：新增"设置…"（默认项，加粗），双击托盘图标打开设置；接上热键 `open_settings`（默认 None）。
- 校准记录在 INI 中附带日期（`<exe>=<每度计数>;<YYYY-MM-DD>`），旧格式继续兼容。

## Capabilities

### New Capabilities
- `settings-window`: 设置窗口的打开方式与单实例、外观与布局、DPI、控件规则、6 个分页上每个控件与 INI 键的绑定和范围、快捷键捕获与冲突提示、即时生效、与其他入口的双向同步、关闭行为。

### Modified Capabilities
- `tray-and-hotkeys`: MODIFIED「托盘图标」（左键单击延迟到双击间隔后再弹菜单，双击打开设置）、「托盘菜单结构」（加入"设置…"并设为默认项）、「热键动作表」（加入 `open_settings`，共 12 项）、「热键触发提示」（`open_settings` 不弹 toast）、「热键注册与冲突」（设置窗口发起的失败只标红、不弹 toast）；ADDED 打开设置的动作、改键后立即重新注册、按键捕获期间暂停全局热键。
- `configuration`: MODIFIED「[hotkeys] 节」（默认值加入 `open_settings`，捕获产生规范字符串）、「[calibration] 节」（值后可带 `;YYYY-MM-DD`）；ADDED 配置变更通知（ConfigChanged）、设置窗口改动的 300 ms 防抖保存、"恢复默认设置"、"清空已知游戏列表"、界面范围与校验范围一致。
- `overlay-rendering`: MODIFIED「显示条件」，增加预览模式这一例外；ADDED 设置窗口预览强度下限。
- `turn-calibration`: MODIFIED「结果计算、保存与生效」（写入日期）；ADDED 在设置窗口删除记录、从设置窗口发起重测。

> 说明：MODIFIED 都是按 `core-overlay` / `in-game-calibration` / `capture-motion-detection` 现有草稿逐字复制后修改的。`openspec validate` 会提示目标 spec 尚未归档，按 1→2→3→4 的归档顺序届时自然消除。「托盘菜单结构」「热键动作表」「热键触发提示」「[hotkeys] 节」是变更 2、3、4 依次叠加修改的同一批需求，本变更的版本已包含变更 2（`calibrate`、"校准当前游戏…"、"校准列表 ▸"）与变更 3（`toggle_capture`、"截屏运动检测"）的条目；若这些草稿在归档前又有改动，归档本变更前须逐条对照合并，否则会覆盖它们。

## Impact

- 新文件：`src/ui/settings_dlg.h/.cpp`（窗口外壳、Tab、页面切换、防抖保存、预览下限）、`src/ui/pages/page_mask.cpp`、`page_dots.cpp`、`page_trigger.cpp`、`page_calib.cpp`、`page_hotkeys.cpp`、`page_general.cpp`，以及共享的 `src/ui/pages/page_common.h/.cpp`（数值控件绑定、范围、气泡提示）和 `src/ui/hotkey_edit.h/.cpp`（按键捕获框）。
- 修改：`src/res/app.rc` 与 `src/res/resource.h`（7 个对话框模板、控件 ID），`src/app/app.*`（ConfigChanged 分发、`IsDialogMessage`、预览下限、打开设置），`src/config/*`（键元数据表、通知、恢复默认、清空已知游戏），`src/tray/*`（菜单项、双击、热键动作、暂停 / 恢复注册），`src/calib/*`（日期字段、删除接口），`scripts/build_app.cmd`（新源文件）。
- 依赖：`comctl32`（§13 已链接；manifest 声明 v6），不引入第三方库。颜色只用十六进制编辑框 + 色块，不用 `ChooseColor`（需要额外链接 `comdlg32`）。
- 前置：依赖变更 1（Config / 热键注册表 / 托盘 / overlay）、变更 2（校准记录与流程）、变更 3（截屏相关键）。

## 待确认

- **Q20 表不在 DESIGN.md 中**：§12 写"内容见设计问答 Q20 的表"，但 DESIGN.md 没有收录该表。本变更按 §8 的全部键与 §12 的条目自行分配到 6 页（分配方式见 `specs/settings-window`）；如有原表，应以原表为准调整。
- **"立即保存"与防抖**：§8 要求"托盘 / 热键 / 设置窗口的每次改动立即保存"，本次任务要求设置窗口改动 300 ms 防抖后保存。本变更采用：托盘 / 热键仍立即保存；设置窗口在最后一次改动后 300 ms 保存，关闭窗口、"打开配置文件"、退出程序时立即落盘。效果立即生效，不受防抖影响。
- **预览时 overlay 不可见**：§12 说预览滑块"让用户不动鼠标也能看效果"，但设置窗口在前台时 `in_game` 为假，按 §6 / 变更 1 的「显示条件」overlay 根本不显示。本变更规定：预览强度 > 0 时 overlay 进入预览模式，在游戏所在显示器（若在游戏中）或设置窗口所在显示器上绘制遮罩与参照点，此时忽略 `enabled` 与 `in_game`。
- **校准日期没有存储位置**：§12 的校准页要显示"日期"，§10（以及变更 2 的「[calibration] 节」）的存储格式却只有 `<exe>=<counts_per_degree>`。本变更把值扩展为 `<值，3 位小数>;<YYYY-MM-DD>`，读取时兼容旧格式，日期显示为"—"。这会修改变更 2 的两条需求，需要变更 2 的负责方确认。
- **"重测"无法在设置窗口里直接开始**：§10 规定校准必须在 `in_game && cursor_locked` 时开始，而点"重测"时前台是设置窗口。本变更把"重测"定为：显示操作指引（切回该游戏、锁定视角后按 `calibrate` 热键），完成后新结果覆盖旧记录、列表自动刷新；不改变变更 2 的状态机。
- **"恢复默认设置"的范围未定义**：本变更规定为重置 `[general]`（`autostart` 除外）、`[mask]`、`[dots]`、`[trigger]`、`[hotkeys]`、`[capture]` 与 `[detect] exclude`；保留 `[calibration]`、`force_game`、`known_games`、`autostart` 与 `[extra]`。
- **排除名单与"视为游戏"名单的编辑**：§12 的通用页没有列出，但 §8 的 `[detect]` 键需要有界面入口。本变更在通用页加入这两个名单的增删，互斥规则与托盘的两个标记操作一致（加入排除名单时同时从 `force_game` 和 `known_games` 移除；加入"视为游戏"时同时从排除名单移除）。
- **颜色选择**：§12 要求只用 comctl32 系统控件，`ChooseColor` 属于 comdlg32，且不在 §13 的链接清单里。本变更用"RRGGBB 编辑框 + 色块预览"。
- **热键 toast 与注册失败提示**：§9 要求"每次热键触发都在 overlay 上显示 toast"，并且"注册失败 → 托盘 toast"。本变更规定 `open_settings` 热键不弹 toast（设置窗口出现本身就是反馈）；由设置窗口发起的注册失败只在该行标红并写日志，不再弹 toast。
- **按键捕获时全局热键会抢先**：已注册的全局热键会被系统截走，捕获框收不到按键（例如想把某动作改成当前已占用的 `Ctrl+Alt+F9`）。本变更规定捕获框获得焦点期间暂停本程序的全部全局热键，离开时重新注册。
- **控件范围**：DESIGN 只给了默认值。控件的最小 / 最大值直接采用变更 1「值校验与回退」的 INI 合法范围和变更 3 的截屏键范围，本变更只补充了步长（见 `specs/settings-window`）。其中几项范围对滑块偏宽（如 `release_ms` 10–5000），但这样 INI 中任何合法值都能在界面上表示。
- **托盘左键单击与双击冲突**：变更 1 规定"左键或右键单击都打开托盘菜单"，§12 / 本次任务又要求"双击托盘打开设置"。单击若立即弹出模态菜单，就收不到双击。本变更把左键单击改为"系统双击间隔（默认 500 ms）内无第二次点击才弹菜单"，右键仍立即弹出（MODIFIED「托盘图标」）。
