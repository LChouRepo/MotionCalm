# Design

## Context

动机见 proposal.md，行为契约见 `specs/`。本文只讲实现方式。

截屏线程 `CaptureService::Impl::step()` 每次调用 `AcquireNextFrame(16 ms)`：超时 / 只有指针更新 → 不估计；新帧 → `GpuDownscaler::submit`（Draw → CopyResource(staging) → Flush）→ 稍后在 `drain()` 读回 → `MotionEstimator` + `SimilarityEstimator` → 三个 `SpeedHold` → 原子发布。帧的时间以 DDA 的 `LastPresentTime` 为准，估计器的 dt 也来自它。

约束：纯逻辑模块不含 Win32、可单测；截屏线程不忙等；60 Hz 下的现有行为（含 `verify.ps1 -Capture` 的结果）不变。

## Goals / Non-Goals

**Goals:**
- 高刷新率显示器上把处理帧率限制在约 55–109 次 / 秒，60–100 Hz 不抽帧。
- 处理帧之间的间隔尽量均匀、尽量接近目标，不引入额外延迟。
- 估计结果不受抽帧影响（dt 仍按时间戳）。

**Non-Goals:**
- 不提供可配置的目标间隔，不降低 60 Hz 下的处理帧率。
- 不改变超时、只有指针更新、重建、暂停的处理。

## Decisions

### D1. 取到再跳过（按时间戳），而不是推迟 AcquireNextFrame

考虑过的两种做法：

| 做法 | 问题 |
|---|---|
| 处理完一帧后睡到目标间隔再调用 `AcquireNextFrame` | DDA 只保留最新画面，晚取会拿到"累积"的帧，帧的时刻取决于线程何时醒来；`Sleep` / 计时器的精度（毫秒级，取决于系统计时器分辨率）直接变成处理间隔的抖动；睡眠期间也无法及时 `drain()` 读回、发布 |
| **取到每一帧，按 `LastPresentTime` 决定处理还是立即释放**（采用） | 每帧多一次 Acquire / Release（不做降采样与读回，开销很小）；决策只看时间戳，结果确定、可单测；不增加延迟，也不改变截屏线程的阻塞方式 |

被跳过的帧立即 `ReleaseFrame`，不碰纹理；`drain()` 照常调用，上一处理帧的读回仍及时完成；发布值按 `SpeedHold` 的保持规则刷新（与超时时相同的取值），但计入 `skipped` 而不是 `timeouts` / `pointer_only`。参考帧不变，下一处理帧与参考帧的 dt 自然覆盖被跳过的时间。

### D2. "离目标间隔最近的那一帧"规则

`G` = 本帧距上一处理帧的时间，`g` = 本帧距上一到达帧的时间：`G + g/2 ≥ target` → 处理。含义：本帧比目标早到的量（target − G）不大于"等下一帧（约 g 之后）会晚到的量"（G + g − target）时就处理本帧，因此选中的总是最接近目标的那一帧，而不是"第一个超过目标的帧"（后者在 120 Hz 下会变成每 3 帧取 1 帧、40 次 / 秒）。

对周期 p 的均匀帧流：1.5·p ≥ target 时每帧都处理；否则处理间隔 n·p ∈ [target − p/2, target + p/2)，处理帧率在约 55–109 次 / 秒之间。例：120 → 60、144 → 72、165 → 82.5、240 → 80 次 / 秒。

首帧、时间戳非有限或 ≤ 0、时间戳不递增时一律处理并以本帧重新锚定（与限速之前的行为相同）。会话建立 / 关闭、暂停后恢复时 `reset()`，使恢复后的第一帧一定被处理。

### D3. 目标间隔 13.75 ms

不抽帧的最高频率是 100 Hz（1.5·p = 15 ms），最低的需要抽帧的常见频率是 120 Hz（单帧 12.5 ms）。13.75 ms 取两者正中，两边各留 1.25 ms 的时间戳抖动余量；60 / 75 Hz 每个时间戳可容忍约 ±3.7 / ±2.0 ms 的抖动而不丢帧。抖动越过边界时只是在相邻两种抽帧比之间切换，dt 来自时间戳，估计不受影响。

### D4. 诊断

`PerfWindow::skipped` 与 `CaptureDebug::skipped` 计数被跳过的帧；`capture perf:` 行在末尾追加 ` skipped=<n>`（不打乱已有字段）；`frames` 只数处理帧。capturetest 汇总行打印 `skipped=`。

## Risks / Trade-offs

- [高刷新率下的时间分辨率] 240 Hz 时测量间隔从 4.2 ms 变为 12.5 ms；遮罩出现约需 0.1 s，影响可以忽略。相似变换估计按 `baseline_ms`（默认 66 ms）在处理帧中选参考帧，可选的参考帧年龄的粒度变为处理间隔（约 9–18 ms），dt 仍按时间戳，换算不受影响。
- [时间戳抖动] 刚好处在边界附近的刷新率（约 109 Hz）可能在两种抽帧比之间来回切换；只影响处理帧率，不影响速度值。
- [尚无实测] 144 / 240 Hz 上的实际效果与开销需要在真实显示器上用 capturetest 确认（tasks.md 中未勾选的项）。

## Migration Plan

无配置变化。读取 `capture perf:` 行的脚本若按字段名解析不受影响；按"字段个数"解析的需要接受第 8 个字段。
